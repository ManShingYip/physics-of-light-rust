# 工程體系（Engineering）— 兩級分離模型

地位：本 folder 係「非常完善報告」嘅工程卷。
與 `docs/research/`（科學卷）、`docs/PROJECT_PLAN.md`（計劃卷）並列。

## 0. 核心原則：兩個工程師，兩種認知，嚴格分離

| | A 級・系統架構師 | B 級・軟件工程師 |
|---|---|---|
| 認知對象 | 系統、契約、不變量、資料流 | 檔案、函數、build、test、deploy |
| 交付物 | 子系統卡（01）、架構視圖（02）、契約版本 | 代碼、測試、runbook（03） |
| 禁止 | 寫代碼、選庫、談語法 | 改契約、改不變量、增刪子系統 |
| 語言 | 數學＋介面簽名＋圖 | Rust/TS/WGSL＋命令列 |

**點解要分**：數學公式→系統嘅分解係**認知行為**，一旦混入代碼細節，
架構會被實現便利性綁架（例如為咗 shader 方便而扭曲物理邊界）。
分開先至可以各自完善：架構改動有 ADR 紀錄，代碼改動有 runbook 約束。

## 1. 交接協定（Handoff Protocol）
1. **契約變更**（buffer 佈局、簽名、不變量）：
   A 級修 02 檔 → 版本號 +1 → 寫 changelog 行 → B 級先可以動代碼。
2. **純實現變更**（演算法內部、效能、重構）：B 級自由，但 04 追溯矩陣須保持綠。
3. **新子系統**：A 級先出卡（01 格式）→ B 級實現 → 雙方喺 04 簽收。
4. **違例處理**：代碼與契約不符 = bug，無論邊邊啱；先 freeze 再仲裁。

- 每條出現過嘅公式都有卡（01），無孤兒公式。
- 每個 buffer/介面都有契約行（02），無隱含佈局。
- 每條 runbook 命令可直接 copy 執行（03），無「自行調整」字樣。
- 04 矩陣每行五欄齊全；規劃中嘅欄位標 `M#` 里程碑號。
